**Released on 2026-09-30.** Barn 0.9.0 manages both Linux labs and native macOS machines from a single CLI, while improving diagnostics and recovery after interrupted operations. For the latest release, see **[Barn 0.9.2](../0.9.2/)**.

[Install Barn](/docs/start/installation/) · [Download 0.9.0 assets](https://github.com/pgsty/barn/releases/tag/v0.9.0) · [Full changelog](https://github.com/pgsty/barn/blob/v0.9.0/CHANGELOG.md)

## macOS machines on Apple Silicon

`barn mac` creates named macOS 27 virtual machines with a native desktop window, SSH, shared folders, and text clipboard sharing. The first machine installs a shared golden base from Apple's verified restore image, and subsequent machines clone that base with APFS copy-on-write—each getting its own writable disks, credentials, and private subnet.

```bash
barn mac up
barn mac open
barn mac ssh
```

Mac guests require Apple Silicon, macOS 27+, and the native app bundle built from the release tag with Xcode 27 (see the [macOS guide](/docs/start/macos/#install)). In accordance with Apple's Virtualization.framework limit and software license, up to two macOS VMs can run concurrently per Mac across all tools. Mac VM state lives under `~/.barn/mac`, independent of your Linux inventory and untouched by Linux `destroy` or `purge`.

## Easier Linux lab recovery

Re-running `barn up` resumes unfinished setup: you can fix an inventory error after a failed first start and retry in place, or resume an interrupted `destroy`. After a host reboot, if the OS assigns a saved QEMU PID to an unrelated process, Barn detects the mismatched process birth time, marks the VM stopped, and never signals the unrelated process.

Concurrent mutating commands wait up to ten minutes for the deployment lock and report which operation holds it, while read-only status and SSH commands remain available. Execution plans now list each node's data disks, including the default 128 GiB `/data` disk.

## Diagnostics with a next step

Inventory validation errors report the violated rule, value, and source line, and suggest corrections for mistyped `vm_*` fields. Failed external commands preserve the relevant tail of `stderr`, and JSON error responses use a consistent `error` class with optional `reason` and `next` fields.

Host setup explains package and network changes before prompting for `sudo`. Symlinked `~/.ssh/config` files managed by dotfile tools are left untouched; Barn prints the `Include` line for you to add.

## Updated Linux images

Embedded catalog **2026093001** covers **41 artifacts across 9 families**. Debian 12/13 and Rocky Linux 8/9 use Barn-normalized images: Debian includes offline XFS tools and a pre-generated `en_US.UTF-8` locale while keeping `C.UTF-8` as default; Rocky Linux 8 uses its shipped chrony configuration and completes SELinux filesystem labeling during image build to avoid first-boot relabeling delays. Ubuntu retains Canonical's upstream image bytes, with Ubuntu 24.04 (`u24`) as the default guest OS.

```bash
barn image list
barn update
```

`barn update` refreshes the local Linux image catalog without modifying the `barn` binary or existing VM disks.

## Upgrade notes

- The CLI command is `barn`, the default inventory filename is `barn.yml`, state lives under `~/.barn`, and environment variables use the `BARN_*` prefix.
- The `rm` alias has been removed; run `barn purge` explicitly to delete an entire Linux deployment including persistent disks and keys.
- In JSON output, `recreate_required` and `nodes_removed` are now `reason` values under `error: "conflict"`, `resource_conflict` is renamed to `resource`, and missing inventories or unknown images exit with code `2` (`usage`). See the [exit-code reference](/docs/reference/cli/#exit-codes).
- `stop` and `start` preserve all disks, while `recreate` replaces root and non-persistent data disks. See the [storage guide](/docs/start/storage/) for how `up` handles damaged data-disk filesystems during recovery.
