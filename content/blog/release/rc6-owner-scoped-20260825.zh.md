Piglet `1.0.0-rc.6` 是限定于所属用户、使用原生 QEMU 的本地开发候选版。
它在两类 Tier 1 宿主上完成了要求的 Quick 和指定四节点 `full` 配置验证，并加入可持久恢复的特权网络事务。
该候选版未公开发布。

## Durable 原生网络

网络安装和卸载使用由 root 持有、严格限定路径前缀的事务：

- root 规划返回与所属用户、宿主及变更前状态绑定的令牌。
- 执行阶段在宿主全局锁内重新规划，只接受该令牌。
- 首次修改前，系统写入结构明确的事务日志，并同步到磁盘。
- 每个固定操作都必须通过准确的后置条件校验，才能记录检查点。
- 操作中断后，系统阻止普通私有网络修改。继续执行或回滚的恢复计划必须单独取得令牌批准。

Darwin 完成了真实中断后的继续恢复，最终在默认 host 模式下处于受保护、健康的状态。
Linux 在最终对抗性修补前完成了真实安装、回滚/重试、四节点运行、卸载与宿主恢复。
最终修补解决了套接字状态规范化、systemd 启用范围过宽、NetworkManager 顺序和恢复操作字段范围的问题。
随后，源码检查与竞态测试全部通过。

按所有者的最终指令，最后一次修补后停止了虚拟机与网络测试，因此审计后的 Linux 安装/卸载/重新安装重放为**未运行**。最终修补仅有源码检查与竞态测试证据。

## macOS Shared Mode 与子网冲突

默认受支持的模式仍为 socket_vmnet host 模式。shared 模式在已确认空闲的替代子网上通过了双节点验证。
用户必须显式选择该备用模式；它不提供隔离边界。

默认子网曾报错 `VMNET_SHARING_SERVICE_BUSY (1009)`。VirtualBox 是可能的干扰来源，但没有证据证明它导致了该故障。
最终迁移前观察到的子网接口是旧版 Piglet 创建的 `bridge100`。
预检按身份拒绝外部接口，不会因 `.1/24` 地址匹配而接管接口。
操作者可以移除已确认的占用来源，或将整套实验环境迁移到一个规范的 RFC1918 `/24` 子网。迁移会显示警告。
Piglet 不会只修改客机地址，也不会随机选择子网来绕过冲突。
