Barn 0.3.0 replaces implicit catalog refreshes with explicit update commands, reports guest bootstrap failures per node, and streamlines the CLI surface while keeping the Pigsty inventory and fixed-IP deployment model.

## What changed

- **Explicit catalog updates.** `up`, `plan`, and standard `image` commands read the active local catalog snapshot without fetching remote metadata behind the scenes. Run `barn update` to fetch the latest signed catalog from the configured repository, or `barn image sync` to activate a specific URL or local file.
- **Per-node bootstrap diagnostics.** Guest initialization records the active bootstrap stage atomically. Partial failures list each failed node, stage, and error message, and readiness timeouts point directly to `barn logs <node>`.
- **In-place readiness rechecks.** Running guests can re-run readiness verification without restarting QEMU, and partial lifecycle runs still regenerate the host SSH client config for all committed nodes.
- **Native guest interface names.** Netplan matches NICs by deterministic MAC address without renaming guest network interfaces, and `vm_disks[].fs: auto` prefers XFS with automatic fallback to ext4.
- **Streamlined CLI.** The redundant `ss` command and ambiguous root/flag shorthands are removed, and `barn image reset` replaces `reset-manifest` (kept as an alias).

## Install or upgrade

Download the installer and assets from the [Barn 0.3.0 GitHub Release](https://github.com/pgsty/barn/releases/tag/v0.3.0):

```bash
curl -fLO https://github.com/pgsty/barn/releases/download/v0.3.0/install.sh
chmod +x install.sh
BARN_VERSION=0.3.0 ./install.sh
barn version
barn doctor
```

The release includes the Homebrew formula and `amd64`/`arm64` DEB and RPM packages. Existing 0.1.0 and 0.2.0 deployment and catalog state remains compatible.
