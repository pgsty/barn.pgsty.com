Barn 0.4.0 是已由 0.5.0 取代的公开预发布版，属于 1.0 之前的版本。首次运行只需一条命令。
该版本修复了 Debian 与 Ubuntu 镜像上的默认数据盘，并统一全部命令的输出风格。
Pigsty 清单格式、固定 IP 部署模型、状态布局与内嵌镜像目录修订号 `2026082903` 均未变化。

## 变化

- 在终端中，固定 IP 网络尚未安装时，`barn up` 会自动执行 `barn setup`。
  它先展示准备计划，在特权步骤前请求确认，再继续执行。`barn init` 的下一步提示改为 `barn up`。
- `vm_disks[].fs` 默认值改为 `auto`：空白磁盘在客机有 `mkfs.xfs` 时格式化为 XFS，
  否则为 ext4，与 Pigsty 的 Vagrant 流程一致。旧的 `xfs` 默认值在不带 xfsprogs 的
  Debian 与 Ubuntu 镜像上会失败。按旧默认值创建的部署不会被报告为漂移，持久盘
  也保持兼容。
- 客机的错误标记携带失败命令的最后一行输出，`up` 会报告
  `guest bootstrap failed during data-disks: xfs requested but mkfs.xfs is unavailable`，
  而不是只有退出码。
- 生命周期命令与 `status` 打印节点表，`up` 成功后给出 `next: barn ssh <node>`。
  没有变化时 `plan` 与 `validate` 只打印一行；`image list`、`network status`、`doctor`
  与预检错误使用没有机器码的自然语句；`spec hash` 等内部信息只在 `--json` 中出现。
  未知节点名的错误会列出现有节点。
- `barn ssh <node> -- 'df -h /data; id'` 会把远程命令按 OpenSSH 的方式原样传递。

## 升级说明

对于由 0.3.0 或更早版本创建、`/data` 从未挂载的 d13、d12 或 Ubuntu 节点，执行一次 `barn recreate <node>`。
这些镜像的数据盘会格式化为 ext4，Enterprise Linux 镜像的数据盘则使用 XFS。
在没有终端的自动化中，若宿主尚未准备好，运行 `up` 前仍需执行 `barn setup --yes`。

## 安装或升级

从 [Barn 0.4.0 GitHub 发布](https://github.com/pgsty/barn/releases/tag/v0.4.0)
下载安装器与资产：

```bash
curl -fLO https://github.com/pgsty/barn/releases/download/v0.4.0/install.sh
chmod +x install.sh
BARN_VERSION=0.4.0 ./install.sh
barn version
barn doctor
```

同一预发布附带 Homebrew 配方与 amd64/arm64 DEB/RPM 软件包。现有部署与
镜像目录状态仍可读取。
