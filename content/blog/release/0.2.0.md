Barn 0.2.0 was the public pre-1.0 release superseded by 0.3.0. It retains the Pigsty inventory and on-disk deployment format from 0.1.0.
It fixes network and selected-node convergence issues found in the final native replay.

## What changed

- A less-specific VPN exclusion such as `10.0.0.0/8` no longer blocks
  Barn's owned `10.10.10.0/24`. Equal or more-specific foreign routes still block the operation.
  Overlapping interfaces, occupied addresses, and a missing owned route also block it.
- `barn up <node>` downloads and prepares only the selected node. Desired inventory peers without state appear as `absent`.
  SSH/hosts/provisioning, UUID and port allocation, lifecycle commands, and persistent-disk checks use the committed node set.
  The inventory retains node definitions for future expansion.
- New guests write `# barn-deployment-host` and remove both that marker and
  the released `# barn-project-host` marker before adding current host rows.
- Command cancellation, structured output, confirmation, `reload`, diagnostic
  redaction, installer retention, and the smaller dependency graph from the
  unpublished intermediate work are included directly in 0.2.0.

## Native and release evidence

The exact source commit completed a macOS arm64/HVF replay with MonoProxy active.
Selected `u24-1` create/SSH/stop/start and incremental cached `el9-1` creation passed. Two-node SSH, five explicit absent peers, and whole-deployment destroy also passed.
On Ubuntu 26.04 amd64/KVM, the release Linux binary inspected an existing four-node deployment and connected to its control guest without changing deployment state.

Local `make check`, source CI, and the complete packaging workflow passed. The
tag workflow built four archives, amd64/arm64 DEB and RPM packages, SPDX SBOMs, a Homebrew formula, an installer, checksums, and release metadata.
GitHub Actions uploads verified CI outputs to a draft for review before public release. It does not add a separate application signature or provenance bundle.

The signed image catalog remains revision `2026082903` with 9 families and 27
architecture artifacts. The default repository remains
`https://repo.pigsty.cc/barn`; `repo.pgsty.com/barn` is an independently
verified source/alternate endpoint, not the compiled default.

## Install or upgrade

Download `install.sh` and the assets from the
[Barn 0.2.0 GitHub Release](https://github.com/pgsty/barn/releases/tag/v0.2.0):

```bash
chmod +x install.sh
BARN_VERSION=0.2.0 ./install.sh
barn version
barn doctor
```

0.1.0 deployment state remains readable. Run `barn status` while retained
VMs are live to converge any pre-release process-birth identity. Existing
guests adopt the new `/etc/hosts` marker when recreated.

Because Barn is still below 1.0, GitHub labels 0.2.0 as a pre-release.
