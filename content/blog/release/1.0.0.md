**Released on 2026-11-05.** Barn 1.0.0 is the first stable release. GitHub's
`releases/latest`, the download installer without `BARN_VERSION`, and the
Homebrew formula select it.

Barn 1.0.0 freezes the command-line contract that 0.9.x converged on and
completes a pre-release audit of destructive operations, data-disk recovery,
catalog integrity, and process cancellation. It embeds signed image catalog revision `2026110502`, including Debian 13
image `20261103.2651.1` for amd64 and arm64.

[Install Barn](/docs/start/installation/) · [Download 1.0.0](https://github.com/pgsty/barn/releases/tag/v1.0.0) · [Source release notes](https://github.com/pgsty/barn/releases/tag/v1.0.0)

## Changes

- **Whole-deployment recreate keeps omitted nodes.** `barn recreate` without
  node selectors refuses an inventory that no longer lists an existing node
  (`conflict`, reason `nodes_removed`, exit 4) before any VM stops. Earlier
  releases destroyed the omitted node without recreating it. Run
  `barn destroy NODE` to remove it, or add it back to the inventory. The
  confirmation lists every node that will be replaced, and the scope is checked
  again under the destruction lock (`deployment_changed` when the applied state
  changed during preflight).
- **Destroying the control node keeps the lab usable.** The first remaining node
  becomes the control node, so `ssh-config`, `hosts`, `exec`, and `provision`
  keep working. Update the inventory's control role, then run `barn up` to
  install its control SSH access.
- **Data disks are reset only on recognized corruption.** Blank disks are
  initialized. An ext4 or XFS filesystem is reset only when the checker reports
  recognized corruption, including on a persistent disk. Partition tables,
  signatures without a UUID, unsupported filesystem features, and unknown
  checker failures keep their data and produce a warning. Existing guests
  receive the updated helper on their next `barn up`.
- **One confirmation before host changes.** On a terminal, `up`, `start`,
  `restart`, and `reload` show the host-preparation plan and ask once before
  installing packages or the Barn network. Without a terminal they report what
  is missing; run `barn setup --yes` for unattended preparation.
- **`purge` asks on a terminal.** It lists the scope and requires typing
  `purge`; `--yes` or `--force` skips the question. Scripts without a terminal
  keep the previous no-prompt behavior.
- **`--yes` for destruction.** `destroy`, `recreate`, `mac destroy`, and
  `mac recreate` accept `--yes`. `--force` keeps working, and
  `mac stop --force` still powers the VM off.
- **Catalog failures exit 7.** A catalog signature or signed revision that does
  not verify exits 7 (`integrity`, reason `catalog_signature` or
  `catalog_equivocation`). Permission and I/O errors on a cached signature
  remain runtime failures (exit 1). Both official repositories share the
  embedded upgrade baseline, and a new trusted signature over identical catalog
  bytes is accepted.
- **Cancellation reaches `sudo`.** Cancelled commands receive SIGTERM, which
  `sudo` forwards, and Barn waits at most 10 seconds for the process and its
  inherited pipes.
- **Host networking and Mac images.** `barn network uninstall` keeps global
  networkd unit state when other host links exist (`preserve_networkd`,
  `checks.networkd`). Mac image pruning keeps bases that interrupted recreates
  still reference.
- **CLI.** `barn` without a command prints the complete help; `--json` and
  `--yaml` keep the `actions[]` document. Explicit `--json`, `--yaml`, and
  `--verbose` override `BARN_OUTPUT` and `BARN_VERBOSE`, and help stays
  available when those variables are invalid.

## Compatibility {#compatibility}

From 1.0.0, incompatible changes to the following require a new major version:
command names, aliases, flags, and argument grammar (including `--` before a
remote command); exit codes and the structured `error` and `reason` values;
existing `--json` and `--yaml` fields; the inventory format and existing
`vm_*` keys; `BARN_*` environment variables; and the deployment and Mac state
under `BARN_HOME`. New output fields may appear in minor releases. Text output,
help wording, progress lines, and log contents may change in any release, so
scripts should read `--json` or `--yaml` and exit codes.

Two script-facing behaviors stay as they are in 1.x. Without `--yes`, `network`
and `hosts` `install`/`uninstall` print the plan and exit 0 when stdin is not a
terminal or the output is structured; check `applied` or pass `--yes`. `destroy`
and `recreate` without node arguments apply to the whole deployment.

## Upgrade

```bash
curl -fLO https://github.com/pgsty/barn/releases/latest/download/install.sh
bash install.sh
```

Set `BARN_VERSION=1.0.0` to pin this release. On macOS, run `brew upgrade barn`;
on Linux, install the DEB or RPM package. Upgrading from 0.9.3 keeps VM disks,
SSH keys, state, and configuration under `~/.barn` and requires no recreation.
Stop macOS VMs before replacing the native component.

Check scripts for four changes: catalog signature failures exit 7 instead of 1,
a whole-deployment `recreate` exits 4 when the inventory omits an existing
node, interactive `up` asks before preparing the host, and `purge` asks on a
terminal.

Security fixes land in the latest 1.x patch release; 0.x releases receive no
further fixes. See the [Linux quick start](/docs/start/tutorial/) and
[Mac guide](/docs/start/macos/).
