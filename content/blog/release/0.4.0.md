Barn 0.4.0 was the public pre-1.0 release superseded by 0.5.0. It provides a one-command first run and fixes the default data disk on Debian and Ubuntu images.
All commands use the same output style. The Pigsty inventory format, fixed-IP deployment model, state layout, and embedded image catalog revision `2026082903` remain unchanged.

## What changed

- In a terminal, `barn up` runs `barn setup` if the fixed-IP network has never been installed.
  It shows the plan, requests confirmation before the privileged step, and then continues startup. `barn init` points to `barn up`.
- `vm_disks[].fs` defaults to `auto`: a blank disk uses XFS when the guest has `mkfs.xfs`, or ext4 otherwise, matching Pigsty's Vagrant flow. The old `xfs` default failed on Debian and Ubuntu images, which ship
  without xfsprogs. Deployments created with the old default are not reported
  as drift and their persistent disks stay compatible.
- The guest error marker carries the failing command's last message, so `up`
  reports `guest bootstrap failed during data-disks: xfs requested but mkfs.xfs
  is unavailable` instead of an exit status.
- Lifecycle commands and `status` print a node table and, after `up`, a
  `next: barn ssh <node>` hint. `plan` and `validate` print one line when nothing changes.
  `image list`, `network status`, `doctor`, and preflight errors use plain sentences without machine codes.
  `spec hash` and other internals moved to `--json`. Errors about an unknown node list the nodes.
- `barn ssh <node> -- 'df -h /data; id'` passes the remote command exactly as
  OpenSSH does.

## Upgrading

If a d13, d12, or Ubuntu node from 0.3.0 or earlier never mounted `/data`, run `barn recreate <node>` once.
The disk then uses ext4 on those images and XFS on Enterprise Linux images. Automation that runs `up` on an
unprepared host without a terminal still needs `barn setup --yes` first.

## Verification boundary

Source commit `8ecb8476c7dbc934d8cbbee935ac53884d00fcdb` passed the complete
local source gate. Checks included unit and race tests, vet, Staticcheck, deadcode, errcheck, and
`govulncheck`. They also covered shell and module checks, four target builds, image-pipeline and installer boundaries, and dependency licenses.
Before publication, the tag workflow repeated these checks and built and verified every archive, native package, SBOM, and the installer.

The new first-run path (`up` running `setup`) is covered by unit tests and was
not replayed on a fresh host before this release. The dated macOS arm64/HVF and
Ubuntu amd64/KVM evidence remains listed on the
[Status](../../../docs/about/history/) page; source, package, release, and
native-host evidence remain separate gates.

## Install or upgrade

Download the installer and assets from the
[Barn 0.4.0 GitHub Release](https://github.com/pgsty/barn/releases/tag/v0.4.0):

```bash
curl -fLO https://github.com/pgsty/barn/releases/download/v0.4.0/install.sh
chmod +x install.sh
BARN_VERSION=0.4.0 ./install.sh
barn version
barn doctor
```

Homebrew formula and amd64/arm64 DEB/RPM packages are attached to the same
pre-release. Existing deployment and catalog state remains readable.
