Barn 0.8.0 cuts down on manual cleanup after interrupted host setup or partial VM starts, and refreshes the Debian and Ubuntu images while preserving previous catalog artifacts and existing VM identities.

## What changed

- **Host preparation follows the command.** Interactive `start`, `restart`, and `reload` can install missing host tools and bring an inactive Barn network back online. On macOS, first-time network installation locates or installs Homebrew (or downloads and verifies the pinned archive) before prompting for administrator credentials, preventing Homebrew from invalidating an earlier `sudo` token.
- **Failed nodes do not block independent peers.** During `up` or `start`, a missing host share fails only the affected node while healthy stopped peers continue to start. Errors report both the missing host source path and guest mount point without creating empty placeholder directories, and `restart`, `reload`, and `recreate` verify share paths before stopping running VMs.
- **Recovery preserves identity.** If a deployment public key is missing, Barn derives it from the existing private key; if the private key is lost, Barn prints backup recovery steps rather than generating a replacement keypair that existing guests would reject. macOS `socket_vmnet` log-directory recovery preserves network ownership markers to avoid false subnet-conflict errors.
- **Failures keep their context.** Scoped retry hints preserve custom `-f` inventory paths, `--repo` overrides, and command names (a failed `start` suggests `start`). Initial setup and its retry share a single operation ID, bounded event logs can be written and read before deployment state exists, and inspecting uncached image metadata no longer requires `qemu-img`.
- **Accurate cleanup summaries.** Deleting persistent disks or running `purge` reports the final deleted state without listing the same disks as both retained and removed. Orphaned disks from previously removed nodes no longer block `destroy` of the remaining lab.

## Install or upgrade

```bash
curl -fLO https://github.com/pgsty/barn/releases/download/v0.8.0/install.sh
chmod +x install.sh
BARN_VERSION=0.8.0 ./install.sh
export PATH="$HOME/.local/bin:$PATH"
barn version
```

For an existing lab, inspect `barn plan` and run `barn up`. `start` powers on existing nodes as-is, while `up` applies inventory changes and retries unfinished guest bootstrap. See the [storage guide](../../../docs/start/storage/) for how `up` handles damaged test data disks during recovery.

## Validation and limits

Four hosts—two macOS `arm64`/HVF machines (`m1`, `m5`) and two Linux `amd64`/KVM machines (`m0`, `m3`)—completed the 7-distro `pro` acceptance pass covering Rocky Linux 9.8/10.2, Debian 12.15/13.7, and Ubuntu 22.04.5/24.04.5/26.04.1. Candidate `6d7870e` performed a clean initialization from the LAN repository, and runtime candidate `1c054a0` upgraded in place and passed repeated healthy `up`, `stop`/`start`, two rounds of guest SSH, data-disk checks, Ansible configuration reads, and control-node lateral SSH (plus 7-node Ansible ping on both Macs) while preserving VM UUIDs, image identities, and disk inodes.

**Known limitations in 0.8.0:**
- macOS host directory sharing for Linux guests remains blocked by upstream QEMU `virtfs` directory-descriptor behavior on Darwin; preflight now diagnoses this earlier.
- A missing control-node guest private key is now detected even when an older ready marker exists, though restoring peer SSH still requires recreating the control node. See the [validation history](../../../docs/about/history/) for the full dated test matrix.
