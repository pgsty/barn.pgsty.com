**Release preparation, updated 2026-11-12.** Barn 1.2.0 is a local candidate; publication is pending. The current stable release is [Barn 1.1.0](/blog/release/1.1.0/).

## Upgrade from 1.1.0 {#upgrade-from-110}

The candidate changes omitted Linux CPU/memory defaults from 2 vCPUs / 4 GiB to 1 vCPU / 2 GiB. This affects existing inventories that omit these fields when the candidate reads them. To retain the previous defaults, set `vm_cpu: 2` and `vm_mem: 4GiB` under `all.vars`, preserve any per-host overrides, and inspect `barn plan` before applying changes. Existing applied VMs keep their resources until a resource-changing operation is requested. Root and data-disk defaults remain 64 GiB and 128 GiB respectively.

## VM resources {#vm-resources}

The candidate adds `--cpu/-C`, `--mem/-M`, `--scale/-S`, and `--disk/-D`, alongside image and architecture selection. The corresponding `BARN_*` environment variables provide defaults, and command-line values take precedence. Generated inventories save the base settings. Plans, validation, status, and lifecycle output display effective resources as `SPEC` labels such as `2c4g`; JSON includes numeric resources, their bases, multiplier, and input sources.

`resize --disk/-D` grows existing root disks. Barn stops QEMU before enlarging the disk, verifies the last plain partition and ext4/XFS filesystem inside the guest, and persists recovery stages so an interrupted operation can resume. Shrinking and unsupported root layouts are rejected. The implementation and regression tests are in `cmd/barn/vm_inputs.go`, `cmd/barn/vm_inputs_test.go`, `internal/private/root_resize.go`, and `internal/private/root_resize_test.go`.

## Lifecycle concurrency {#lifecycle-concurrency}

`--parallel/-p` controls concurrency for Linux lifecycle commands. The default is the logical CPU count minus two, with a minimum of one. Zero runs all selected nodes concurrently; a positive value sets the maximum. Retry commands preserve explicit overrides. Coverage is in `internal/private/concurrency_test.go` and `cmd/barn/lifecycle_parallel_test.go`.

## Inventory host names {#inventory-host-names}

The reviewed working tree adds `all.vars.vm_hosts` and `barn hosts install -f INVENTORY`; these changes still need to enter the release commit. Extra host-side service names can be combined with node names and published before any VMs exist. Preview with `barn hosts install -f pigsty.yml --json`, then apply with `barn hosts install -f pigsty.yml --yes`. Omitting `-f` keeps using applied node names. Identical mappings merge case-insensitively; conflicting addresses fail. These mappings leave VM identity and guest configuration unchanged. See [extra host mappings](/docs/reference/configuration/#local-hosts).

The dependency-license inventory matches the modules linked into the CLI and helper. See `packaging/toolchain.env` and `go.mod` in local commit `6ab0cd5`; the reviewed remote main still points to 1.1.0.

A real RPM fixture confirmed both header and extracted payload timestamps, and the complete packaging snapshot passed with the updated check.

The candidate embeds signed catalog revision `2026110502`. On 2026-11-11, `make catalog-check` verified both official repositories, activated each signed catalog in a fresh temporary data root, confirmed byte-for-byte agreement with the embedded catalog, and checked availability and sizes for all 17 stable artifacts. The default is Ubuntu 24.04 on the host's native architecture.

## Local validation {#local-validation}

The [2026-11-12 readiness review](/blog/design/release-1-2-0-readiness/) adds complete snapshot packaging with the native app, Linux/KVM failure-recovery acceptance, and the 15-stage Mac lifecycle run. It also lists the remaining gates for the final release commit and signed assets.

Validation on 2026-11-11 used the modified source tree based on commit `1e24768` and the pinned toolchain:

- `make check` passed, including unit/race tests, static analysis, four-target cross-builds, installer and image-pipeline checks, and the dependency-license inventory.
- `make mac-native-test` passed the native component tests.
- `make release-snapshot SNAPSHOT_DIST=.goreleaser-refresh-1.2.0-20261111` passed archive, DEB/RPM, SPDX, checksum, timestamp, paired-helper, and package/archive parity checks. The existing snapshot rule derives `1.1.1-next` from the last published tag; the local development binary reports `1.2.0-dev.1`. Snapshot validation covers the CLI/helper archives and Linux packages; formal Mac assets follow the signed-payload release workflow.
- The candidate's `barn update --repo https://repo.pigsty.io/barn` activated the signed official catalog in a fresh temporary `BARN_HOME`, with bytes matching the embedded catalog.
- The documentation production build and the build including drafts passed their internal link and asset checks.

`govulncheck` found zero vulnerabilities in imported packages or reachable symbols. Its module-level report lists [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932) in `golang.org/x/crypto/openpgp`; Barn does not import that package.

## Build the candidate {#build-the-candidate}

From the prepared source tree, with Go 1.27.4:

```bash
BARN_VERSION=1.2.0-dev.1 make build
./bin/barn version
```

The published installer continues to select 1.1.0. The final release date and download instructions will be added after 1.2.0 assets are public.
