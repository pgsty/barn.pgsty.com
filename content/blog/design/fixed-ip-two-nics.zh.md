本文介绍 Barn 0.9.0 的 Linux 网络设计。[Mac 虚拟机](/zh/docs/start/macos/)独立管理。

Pigsty 清单用稳定地址标识机器。PostgreSQL 复制、etcd 成员、HAProxy 后端、VIP、
监控目标与 Ansible 都假设 `10.10.10.11` 始终代表同一个节点。回环端口转发可以把 SSH 或
PostgreSQL 暴露给宿主，却无法把这种网络身份提供给其它节点。

因此，每个正常 Barn 节点都有两张网卡：一张提供 NAT 连接，另一张提供固定网络地址。

## 一张网卡不该承担两项冲突职责

| 网卡 | 地址方式 | 职责 |
| --- | --- | --- |
| 管理网卡 | QEMU 用户态 NAT、DHCP | DNS、默认路由、互联网出站与回环 SSH 备用路径 |
| 私网网卡（按 MAC 匹配） | 清单固定地址 | 宿主到节点、节点间、Ansible、Pigsty 服务与 VIP 流量 |

Barn 使用确定的 MAC 地址匹配两张虚拟网卡，不修改网卡名称。镜像的网络栈决定客机中的名称，通常是 `eth0` 或 `enp0s4`。
MAC 与地址契约决定网卡职责。

管理网卡让新的云镜像在安装应用前就能访问软件仓库。宿主无需添加 NAT 规则或 DHCP 服务。

私有网卡使用一个确定的 RFC1918 地址，不设置默认路由或 DNS。客机初始化会检查这些属性。
从 0.7 起，私网检查失败会记录 `private-network` 警告；只要管理 SSH 与客机身份可用，客机仍可就绪。
因此，操作成功并不保证固定 IP 完全连通。
部署依赖该网卡的服务前，应检查警告并测试相应宿主/节点间连接，修正原因后重复 `up`。

> [!NOTE]
> 这套拓扑属于 Barn 的正常生命周期，并不是可选的
> “私网模式”。当前平台边界见[设计参考](/zh/docs/about/design/)。

## 地址规划归主机清单所有

所有受管节点位于同一个规范 RFC1918 `/24`：

| 范围 | 含义 |
| --- | --- |
| `.1` | 宿主侧私有网络地址 |
| `.2`–`.8` | 保留边界，包括有效的二层 VIP 空间 |
| `.9`–`.254` | 节点固定地址 |

客机私有网卡不请求 DHCP：cloud-init 直接得到清单已声明的准确地址。macOS
vmnet 配置的 DHCP 范围止于 `.8`，受管节点从 `.9` 开始；Linux 使用桥接与客机静态地址。
因此，虚拟机地址不依赖租约数据库。Ansible 从首次连接到后续部署都使用同一地址。

自动生成配置时，如果默认子网被占用，setup 可以从有限候选中选择空闲网段。Barn 不会为避开冲突而改写用户显式提供的清单。
宿主接口、所有节点、Pigsty 地址与别名必须使用同一子网。

## 后端因平台而异，客机契约保持一致

客机在所有支持宿主上看到相同拓扑，Barn 则跟随宿主真正的网络管理者：

- **macOS：** 固定版本的 `socket_vmnet` 服务提供私有链路。Host 模式默认，Shared 模式
  必须显式选择；QEMU 仍以普通用户运行。
- **NetworkManager 活跃的 Linux：** Barn 通过 `nmcli` 创建自有 `barn0` 网桥，
  并与活跃的 firewalld 策略配合。
- **systemd-networkd 管理的 Linux：** Barn 安装自有服务单元，并借助发行版
  `qemu-bridge-helper` 保持 QEMU 非特权。
- **networkd 尚未启动：** 只有预变更扫描能证明现有服务单元不会接管真实宿主网卡时，才允许
  激活它。

在桌面或 RHEL 家族宿主上启动 networkd，可能破坏宿主网络。能够写入 `.network` 文件并不代表可以安全启动 networkd。
因此，Barn 使用当前管理宿主网络的组件。

## 宿主网络是一项事务

CLI 退出后，网桥或 vmnet 守护进程仍会继续运行。安装这些组件还需要特权，因此 Barn 使用可逆的宿主事务：

1. 检查路由、接口、服务、属主与已有状态；
2. 修改前打印准确计划；
3. 应用前立即重新检查前置条件；
4. 用 root 所有的状态记录 Barn 创建了什么、此前存在什么；
5. 证明普通用户 QEMU 确实可以接入；
6. 全部就绪检查通过后才接受安装。

Barn 不会接管使用相同 `.1/24` 的外部接口，也不会覆盖已经修改的自有文件。
已记录节点仍在运行时，Barn 拒绝卸载。卸载只恢复安装记录中的原有状态。操作失败后，Barn 会停止，不会扩大删除范围。

## 接受的取舍

客机互联网流量经过 QEMU 用户态网络。这条路径以部分转发性能换取非特权、跨平台的出网能力。
宿主到客机的流量、复制、服务调用，以及控制节点的软件包分发，都使用私有链路。

管理网卡负责客机初始化所需的连接，私网网卡则提供实验环境所需的稳定地址。
